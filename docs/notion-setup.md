## 組み立てで分かったこと（事実）

| # | 分かったこと | どう対応したか |
|---|---|---|
| 1 | 外部接続（API）からは、プロジェクト側の数式で、関連付けたタスク側の列を直接読めない（「状態 is not a valid property」になる） | タスク側に裏方の数式「集計」（●完了／○未完了／▶次の一歩＋名前／アイデアは空）を置き、プロジェクト側の集計列（ロールアップ）で受けて数えた。裏方の列はページでは隠した |
| 2 | Notion MCPで読むと、数式・集計の列は値ではなく参照（formulaResult://…）しか返らない | Claudeは数式を使わず、元の列（状態・日付・チェック）から④のルールで判定する |
| 3 | 集計列（ロールアップ）の「元の値を表示」は、数式からは文字のつながり（カンマ区切り）として見える | カンマで区切って数えている。タスク名にカンマ「,」が入ると数え方がずれるおそれがある（推測）。名前には読点「、」を使う |
| 4 | タイムラインのビューでも「領域ごとにまとめる」が使えた | 全体マップを領域ごとにまとめた |
| 5 | 保存済みビューを読む方法（view mode）は、無料プランでも回数の上限がない | 朝の秘書は、タスク全部とプロジェクト全部のビューを読む |
| 6 | 外部接続（MCP）からは、ビューの形（リスト→テーブル）を変えられず、ビューを消すこともできない（11/26） | ☀️今日はテーブルのビューを新しく足した。古いリストのビューは名前を「古い今日（消してOK）」にして、シオンに手で消してもらう |

## 11/26の変更（v0.3）

| 変えたもの | 中身 |
|---|---|
| タスクに「済」の列（チェック） | 終わったらシオンが✓。翌朝、朝の秘書が状態＝完了・完了日・次の一歩の印外しを行う |
| やる日の説明 | 「始めたい日。この日から今日の候補に出る（過ぎても失敗ではない）」 |
| サインの数式 | 🟠持ち越しをやめ、⏰期限が近い（今日まで・明日まで・あとN日、3日以内）を足した。✓済みのものには印を出さない |
| 集計の数式 | ✓済みも●（完了）として数える → 進捗率・次の一歩にすぐ反映される |
| ☀️ 今日 | リスト → テーブル（上の表） |
| ホームの説明文 | 「触るのは☀️今日の✓だけ」に変えた |

## 手で直したくなったとき

| やりたいこと | どうする |
|---|---|
| 列やビューを足したい・名前を変えたい | Claudeに頼む（名前を変えると、指示文の中の名前とずれて動かなくなるため） |
| タスクの中身を直したい | Claudeに言う。Notionで直接直してもよい（列の名前と選択肢さえ変えなければ大丈夫） |
| 終わったタスクを片付けたい | ☀️今日の「済」に✓（翌朝、正式に完了になる） |
