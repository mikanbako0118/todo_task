# 設計書：シオンの仕事管理（v0.3）

2026-11-25 作成。v0.2で「目的」「⑦ Claudeの動き方」を足し、Notionの組み立て結果に合わせて直した。v0.3（11/26）で、使ってみた気づきから「やる日＝始めたい日」「済のチェック」「☀️今日をテーブルに」を入れた。「仮」と書いたところは、決めなくても進められるので仮決めしたもの。

---

## 目的（忘れないように）

> **シオンが、毎回入力でき、毎日、見たいときに確認でき、心置きなく実行できる。**

| 目的 | 意味（解釈） | 支える仕組み |
|---|---|---|
| 毎回、入力できる | 思いついた断片を、その場で、形を整えずに出せる | 話すだけ（音声でよい）。清書・分解はClaude（⑦） |
| 毎日、見たいときに確認できる | 朝は向こうから届く。気になったら開ける | 朝のDiscord／Notionのホーム1ページ／仕事ノート |
| 心置きなく実行できる | 忘れる心配・迷い・抱え込みがない | 全部Notionにある／次の一歩が小さい／今日は5件まで／Claudeに任せられることは任せる（⑦） |

迷ったときは、この3つに効くかどうかで決める。

---

## 結論（3行）

- **シオンがやることは4つだけ**：話す・見る・紙に写す・終わったと言う。登録・分解・催促はすべてClaude。
- **Notionはデータベース2つ**（プロジェクト／タスク）。アイデアもタスクDBの「状態」で受ける。ビューは4つ。
- **毎朝7時ごろ**、Discordの専用チャンネルに「今日の一枚」（最大5件）が届く。それを紙に写して動く。

## ② NotionのDB設計

### 全体の形

```
📒 仕事管理（ページ）  ← ここを開けば全部見える「ホーム」
 ├─ ☀️ 今日          （タスクDBのビュー）
 ├─ 🗺 全体マップ     （プロジェクトDBのビュー）
 ├─ 🗂 ボード         （タスクDBのビュー）
 └─ 📦 データ置き場   （ふだんは開かない）
      ├─ 📁 プロジェクト（DB本体）
      └─ ✅ タスク    （DB本体。📅カレンダーはここのタブ）

   📁 プロジェクト  1 ──── 多  ✅ タスク
   （納屋の片付け）          （燃えるゴミだけ袋に入れる／金属ゴミを集める／…）
```

### 📁 プロジェクトDB（9列）

| 列 | 種類 | 中身 | 入れる人 |
|---|---|---|---|
| 名前 | タイトル | 例「納屋の片付け」 | Claude |
| 領域 | セレクト | 御伽荘／個人／藝術農民／交響する農村／交響する氷見（11/26に交響の2つが増え、11/27に農業をなくした） | Claude |
| 状態 | セレクト | 構想／進行中／保留／完了 | Claude |
| ゴール | テキスト | 終わったら何が目に見えるかを1行で | Claudeが2〜3案 → シオンが選ぶ |
| 開始日 | 日付 | 始めた日 | Claude |
| 期限 | 日付 | 目安でよい（タイムラインに帯を出すため必須） | Claudeが案 → シオンが選ぶ |
| タスク | リレーション（DB同士のつながり） | タスクDBと自動でつながる | 自動 |
| 進捗率 | 数式 | 完了したタスク ÷ アイデア以外のタスク。「●○○○○ 1/4」のように表示 | 自動 |
| 次の一歩 | 数式 | 「次の一歩」に印が付いた未完了タスクの名前を表示 | 自動 |
| サイン | 数式 | 🔴期限切れ／🟡遅れ気味／💤止まっている／⚠️次の一歩なし | 自動 |
| 集計・最後の動き | 集計（ロールアップ） | 裏方。上の数式の材料。ページでは隠してある | 自動 |

※「タスク」「集計」「最後の動き」は自動の列なので、人が意識するのは9列。
※裏方の列が要る理由：Notionの外部接続では、プロジェクト側の数式からタスク側の列を直接読めなかったため（組み立て時に確認した事実）。

**状態の意味**

| 状態 | 意味 | 例 |
|---|---|---|
| 構想 | まだ始めていない大きなアイデア | 久目の無人販売 |
| 進行中 | 動かしている | 納屋の片付け |
| 保留 | 自分の意思で止めている（季節待ちなど）。催促しない | 冬の間の田んぼ作業 |
| 完了 | 終わった | |

「保留」を置く理由：止めているのに毎朝「止まっています」と言われると、見るのが嫌になるため（推測）。

### ✅ タスクDB（13列。ふだん見えるのは7列）

| 列 | 種類 | 中身 | 入れる人 | ふだん |
|---|---|---|---|---|
| ✓ | チェックボックス | 終わったら✓。翌朝、朝の秘書が正式に完了にする（v0.3で「済」として追加。11/27に列名を「✓」に） | **シオン** | 見える |
| タスク | タイトル | （11/27に列名を「名前」→「タスク」に）「対象＋具体的な動作」。例「入口の燃えるゴミだけ袋に入れる」 | Claude | 見える |
| プロジェクト | リレーション | 1つ。単発のことや、まだ行き先のないアイデアは空でよい | Claude | 見える |
| 状態 | セレクト | 💡アイデア／これから／進行中／待ち／完了 | Claude | 見える |
| 次の一歩 | チェックボックス | **1プロジェクトに1つだけ**印を付ける | Claude | 見える |
| やる日 | 日付 | **始めたい日**。この日から今日の候補に出る。過ぎても失敗ではない（v0.3で意味を変えた） | 朝の秘書・Claude | 見える |
| 期限 | 日付 | 守らないと困る日だけ入れる | Claude | 見える |
| 目安時間 | セレクト | 15分／30分／1時間／2時間以上 | Claude | 見える |
| サイン | 数式 | 🔴期限切れ／⏰期限が近い（3日以内）／💤止まっている／🤖Claude（任せるタスク） | 自動 | 見える |
| 担当 | セレクト | シオン／Claude（後でメンバーを足せる） | Claude | 隠す |
| 出どころ | セレクト | チャット／音声／紙／Discord／ブレスト | Claude | 隠す |
| 完了日 | 日付 | 完了にした日 | Claude | 隠す |
| 最終更新 | 最終更新日時 | 自動 | 自動 | 隠す |
| 集計 | 数式 | 裏方（●完了／○未完了／▶次の一歩）。プロジェクト側の数式の材料 | 自動 | 隠す |

### 叩き台から変えたところ

| 変更 | 理由 |
|---|---|
| タスクの「開始日」→「**やる日**」 | v0.2では「どの日の一枚に載せたか」の意味にした。v0.3で「始めたい日」に変えた（下） |
| 状態「次にやる」→「**これから**」 | 「次の一歩」と言葉が似ていて、Claudeもシオンも混ざりやすい |
| 「次の一歩」を**タスク側のチェック**にした | プロジェクト側に文字で書くと、タスクと二重になってずれる。印方式なら、完了した瞬間に「⚠️次の一歩なし」が自動で出る |
| 「停滞」の数式 →「**サイン**」1列にまとめた | 期限切れ・持ち越し・停滞を別々の列にすると列が増える。1列に絵文字で出す |
| 「完了日」を足した | 「最終更新」は何かを直すたびに変わるので、「いつ終わったか」が分からなくなる。仕事ノートの「できた数」にも使う |
| 担当は「人」ではなく**セレクト**（仮） | Notionの「人」の列は、Notionに招待した人しか選べない。メンバーはNotionを使わない前提なので、名前の選択肢にしておく |
| プロジェクトの状態に「保留」を足した | 上の「状態の意味」を参照 |
| v0.3：やる日の意味を「載せた日」→「**始めたい日**」にした | 「決めても、その日にできないことのほうが多い」（シオンの気づき）。過ぎるたびに🟠持ち越しが付くと、責められている感じになって続かない。急ぎの印は期限だけにした |
| v0.3：「**済**」のチェックを足した | Notionで終わったものに✓を付けたい（シオンの要望）。状態を選び直すより1タップで済む。正式な完了（状態・完了日）は翌朝、朝の秘書がやる |
| v0.3：「始めなきゃいけない日」の列は作らない | タスクは15〜30分に小さくしているので、始めなきゃいけない日は期限とほぼ同じになる。準備に時間がかかるもの（注文して届くまで等）は、期限を前倒しで置く |

### アイデアの置き場：タスクDBの「💡アイデア」で受ける（別のDBは作らない）

| | A：タスクDBの状態「アイデア」（採用） | B：別のDB「アイデア箱」 |
|---|---|---|
| Claudeが扱うDB | 2つのまま | 3つになる |
| アイデア → タスクにするとき | 状態を変えるだけ | 別のDBへ移し替え（漏れやすい） |
| 探すとき | 1か所 | 2か所 |
| 気をつけること | 普段のビューに混ざる → 「今日」「全体マップ」では隠し、ボードの左端の列にだけ出す | — |

- タスクくらいの大きさのアイデア → タスクDBの「💡アイデア」
- プロジェクトくらいの大きさのアイデア → プロジェクトDBの「構想」
- 流れて消えないように、**14日以上たったアイデアは、朝の秘書が1日1件「やる？やめる？」と聞く**
- やめたアイデアは、確認してからNotionのゴミ箱へ（ゴミ箱から30日は戻せる）

## ③ ビュー設計（4つ）

| # | ビュー | 形 | 一目で分かること | 中身の条件 |
|---|---|---|---|---|
| 1 | ☀️ 今日 | テーブル（v0.3でリストから変更） | 今日の候補と、終わったものの✓ | やる日が今日以前・状態が「これから／進行中」。✓→期限→やる日の順（✓は下に沈む）。列は ✓・タスク・目安時間・プロジェクト・サイン。タブに📅カレンダー（やる日で並べる）も置いた |
| 2 | 🗺 全体マップ | タイムライン（プロジェクト） | どのプロジェクトがいつまでか、どれが遅れているか、それぞれの次の一歩 | 状態が「進行中／保留」。帯の横に 進捗率・次の一歩・サイン。領域でまとめる（グループ表示が使えることを確認済み） |
| 3 | 🗂 ボード | ボード（タスクを状態別） | アイデア〜完了のどこに何がたまっているか | 完了は直近7日分だけ。カードに プロジェクト・目安時間・サイン |
| 4 | 📅 カレンダー | カレンダー（タスクの始めたい日。v0.3で期限から変更） | いつ何に手を付けるつもりか、予定が詰まっている週 | 状態が「完了」「アイデア」以外 |

1〜3は「仕事管理」ページに並べて置く（ここだけ開けばよい）。カレンダーはタスクDBの中のタブにする。

**作らないもの**

| 依頼にあったもの | 今回の扱い | 理由 |
|---|---|---|
| 担当別ボード | 作らない（チーム参加時に、ボードのグループを「担当」に切り替えるだけ） | 今は1人なので、全部「シオン」の列に入り、何も分からない |
| タスクのタイムライン | 作らない | 小さなタスクが数十本並ぶと、図として読めない。時間の流れはプロジェクトで見る |

**スマホでは**：「今日」と「ボード」が見やすい。タイムラインはPC向き（推測）。

## ④ ルールの定義

Claude（会話）と朝の秘書は、このルールだけで判断する。

### 次の一歩の基準（全部満たす）

| # | 基準 | 良い例 | ダメな例 |
|---|---|---|---|
| 1 | 15〜30分で終わる | 入口の燃えるゴミだけ袋に入れる | 納屋を片付ける |
| 2 | 範囲が1つ（場所1つ／種類1つ／数1つ） | 商品を**1つだけ**撮影する | 商品写真を撮る |
| 3 | 目に見える動作で終わる | 田植機の相場を**メモに3件書く** | 田植機について調べる |
| 4 | 終わったことが目で見て分かる | 袋が1つできる | 「だいたい片付いた」 |
| 5 | その場で始められる（足りない物があるなら「買う」が次の一歩） | ゴミ袋を1パック買う | （袋がないのに）袋に入れる |

**使わない言葉**：片付ける・整理する・考える・検討する・計画する・準備する・進める（単独で使うとき）。

> 指摘：依頼書の「動詞で始める」は英語の書き方の発想。日本語は動詞が最後に来るので、「**具体的な動作で終わる**」と読み替えた。

**分解の深さ**：最初の1つ（次の一歩）だけを15〜30分にする。ほかのタスクは1時間以内のかたまりでよい。次の一歩が終わったら、次の候補を15〜30分に切り直す。理由：最初から全部を15分単位に刻むと数が膨らみ、見るだけで疲れる（推測）。

### 状態の判定（日付は日本時間）

| 判定 | 定義 | 対象外 |
|---|---|---|
| 🔴 期限切れ | 期限が今日より前で、未完了 | アイデア |
| ⏰ 期限が近い | 期限が今日〜3日後で、未完了 | アイデア |
| 💤 止まっている（タスク） | 進行中のまま3日、または待ちのまま7日、更新がない | |
| 💤 止まっている（プロジェクト） | 進行中なのに、7日間どのタスクも動いていない | 保留・構想 |
| 🟡 遅れ気味（プロジェクト） | 期間の経過割合が、進捗率より30ポイント以上大きい（例：期間の70%が過ぎたのに進捗40%） | |
| ⚠️ 次の一歩なし | 進行中のプロジェクトに、印の付いた未完了タスクがない | 保留・構想 |

- 完了とみなすのは、状態が「完了」か、✓の列に✓があるもの。
- やる日（始めたい日）が過ぎても印は付けない（v0.3で🟠持ち越しをやめた）。14日以上たったものだけ、朝の秘書が1日1件「まだやる？分ける？」と聞く。

### 今日の一枚

- 「今日やる5件」ではなく「**今日の候補。上からやれたら十分**」という見せ方にする（v0.3）。
- **上限5件**。シオンのタスクだけ。✓済み・やる日が先のものは入れない。
- 選ぶ順番：
  1. 期限が3日以内のもの（過ぎたものも。期限が近い順）
  2. やる日（始めたい日）が来ているもの（やる日が古い順）
  3. やる日が空の、進行中プロジェクトの「次の一歩」（プロジェクトの期限が近い順）
- 入りきらなかった件数は 📌 に出す。

### 朝の秘書がNotionに書き込むのは2つだけ

- 今日の一枚に新しく載せたタスク（やる日が空のもの）に、やる日＝今日を入れる。これで、Notionの「今日」ビューと紙が一致する。
- ✓の列に✓が付いているのに完了になっていないタスクを、完了にする（状態＝完了・完了日＝✓を付けた日・次の一歩の印を外す）。シオン自身が✓で「終わった」と言ったものなので、確認なしで行う。
- それ以外の状態の変更・削除・次の一歩の付け替えはしない（シオンが確認できない時間に動くため）。

## ⑤ 毎日の運用フロー

| いつ | シオンがやること | 裏でClaudeがやること |
|---|---|---|
| 朝7時ごろ | **見る**：Discordの「今日の一枚」→ **紙に写す** | 朝の秘書がNotionを読み、今日の一枚を作って送る |
| 日中 | 紙を見て動く。終わったら斜線 | — |
| 思いついたとき | **話す**：Claudeアプリに一言（音声でよい） | ゴール案 → 分解 → 「これで登録していい？」→ 登録 |
| 終わったあと（夜でも翌朝でも） | **終わったと言う**：Notionの☀️今日で✓、「〇〇終わった」、または紙の写真 | ✓は翌朝に完了へ。言葉・写真は、完了の候補を一覧 → 確認 → 完了・完了日・次の一歩を更新 |
| 全体を見たいとき | **見る**：Notion「仕事管理」か仕事ノート | — |

確認の返事（「1番で」「はい」）や、Claudeに任せるときの「それで」は「話す」に含まれる。☀️今日の✓は「終わったと言う」の別のやり方（v0.3）。**4つの操作に収まっている。**

### Discordに届く「今日の一枚」の形

```
☀️ 今日の一枚　11/27(金)
━━━━━━━━━━━━━━
上からやれたら十分。残りは明日も候補に出ます
□ 種籾の手配先と注文の締切を確かめる（15分）
　⏰明日まで・来年の米作り計画
□ 本を1か所に集める（30分）
　自室の片付け
□ 不燃ごみを捨てに行く（2時間以上）
　納屋の片付け
全部やると約2時間45分以上

✅ ✓の付いた1件を完了にしました（来年使う田んぼの名前を紙に書き出す）

❓ これやった？
・金属ゴミを1か所に集める
　進行中のまま4日。終わった？
・🤖 入れ物の候補を3件探す
　Claudeが調べられます。方針を見て任せる？

📌 ほかに
・「来年の米作り計画」の次の一歩を決めよう（Claudeに話すと案が出ます）

終わったら「☀️ 今日」で✓。「〇〇終わった」とClaudeに言ってもOK
```

依頼書の5項目との対応：

| 依頼書の項目 | この形での置き場所 |
|---|---|
| 今日の一枚 | ☀️ そのもの |
| 期限切れ・持ち越し | ☀️ の中に🔴⏰で印（期限だけ）。始めたい日が過ぎたものに印は付けない（v0.3）。5件に入りきらない分は 📌 に件数 |
| 停滞・「これやった？」3件 | ❓ にまとめて3件まで |

まとめた理由：別々の見出しにすると、同じタスクが「期限切れ」「今日の一枚」などに何回も出てしまう。**1つのタスクは1回だけ出す**ルールにした。

**❓ の選び方（3件まで・この順・今日の一枚に出したものは除く）**：①待ちのまま7日以上 ②進行中のまま3日以上 ③Claudeに任せられるのに方針がまだのもの（1日1件・日替わり） ④始めたい日から14日以上たったもの（1日1件・日替わり。「まだやる？分ける？」） ⑤14日以上前のアイデア（1日1件・日替わり）。

**☀️ の形**：1行目＝紙に写す文（□ 名前（目安時間））、2行目＝印とプロジェクト名。前の日に✓が付いたものは「✅」の行で知らせる。判定と文面は `prompts/morning-brief.md` のスクリプトで固定した。

## ⑦ Claudeの動き方（v0.2で追加）

詳しくは `docs/claude-policy.md`。要点だけ：

```
 断片 ──→ ①清書「こういうこと？」（2〜3案）──→ 選ぶ ──→ 登録（元の言葉も残す）
                                                    │
                       Claudeにできそう？ ─ はい ──→ ②代行：方針カード → 「それで」→ 実行
                                                    │              → 結果はタスクのページに
                                                    │              → シオンの次の一歩を1つ
                                                    └ いいえ ──→ シオンのタスク
 どこでも ──→ ③散らかさない：新しい置き場を作らない・消さない・1画面に収める
```

| | Claudeに任せてよい | シオンがやる |
|---|---|---|
| 例 | 調べる・比べる／下書き／表・計算・整理 | 買う・申し込む・連絡する・投稿する・お金が動くこと |

- 任せるタスクは、担当を「Claude」にする（画面では🤖Claude）。列は増やさない。
- 代行は、シオンが見ている会話の中だけ。朝の秘書（無人）は代行しない。
- 的外れだったら、ずれた点を選択肢で聞いて1回だけやり直す。それでもずれたら、シオンに戻す。
